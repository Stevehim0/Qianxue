# 记忆系统 - 存储层设计文档

> 讨论日期：2026-03-29
> 状态：存储层讨论完成

---

## 一、总体结构

存储层由三个部分组成：

- **体验层** — 以"我"为视角的主观体验，带情感，会衰减
- **信息层** — 客观实体与关系的知识图谱，带置信度，需验证
- **索引层** — 两层的语义向量索引，用于快速召回

两层独立演化，通过跨层边互相映射。

---

## 二、体验层

### 2.1 节点结构

```
{
  id: "exp_YYYYMMDD_HHmmss",        // 纯时间戳，同一秒视为同一件事
  
  // 四层深度
  L0: { text: "一句话摘要", embedding: [...] },   // 始终被召回，衰减最慢
  L1: { text: "关键要点", embedding: [...] },      // 深思考时展开
  L2: { text: "具体细节", embedding: [...] },      // 深思考时展开
  L3: { raw: "完整原文" },                          // 极少访问，衰减最快
  
  // 情感快照（不变）
  emotion_at_time: {
    category: "喜爱",              // 预定义基础集合 + 自由文本
    intensity: 0.8,
    target: "info_uuid_张三"       // 可选，指向信息层实体
  },
  
  // 上下文快照（自动 + 可选外部传入）
  context: {
    // 自动从状态层读取
    focus: "记忆系统架构设计",      // 状态层的 focus（可为 null）
    mood: "投入",                  // 状态层的 mood.label
    
    // 自动从时间戳推导
    time_of_day: "凌晨",           // 从 created_at 推导
    silence_before: "45分钟",      // 距上一条体验节点的时间差
    
    // 外部系统可选传入（未来扩展）
    task: str | null,              // 外部任务感知系统提供，当前阶段为 null
    extra: {}                      // 扩展字段，预留给未来的外部系统
  },
  
  created_at: "ISO时间戳"
}
```

### 2.2 情感基础类别

预定义第一级（分类和检索用）：

喜悦 / 悲伤 / 愤怒 / 恐惧 / 惊讶 / 厌恶 / 信任 / 期待 / 困惑 / 满足

允许加自由文本补充描述。

### 2.3 边结构

四种类型：

| 类型 | 说明 | 示例 |
|------|------|------|
| temporal | 时序关系，确定性 | A发生在B之后 |
| thematic | 主题相似 | 两次对话都在讨论同一件事 |
| causal | 因果关系 | A导致了B |
| associative | 联想关系 | 想到A就想到B |

```
{
  from: "exp_20260329_1744",
  to: "exp_20260329_1801",
  type: "thematic" | "temporal" | "causal" | "associative",
  weight: 0.0 - 1.0,
  emotion_driver: "喜悦",            // 可选，这条边被什么情感驱动
  created_at: "ISO时间戳",
  decayed_weight: 0.6                // 经衰减后的当前权重
}
```

一对节点之间可以有多条不同类型的边。

### 2.4 衰减因素

权重衰减受三个因素影响：

- **时间** — 越久越模糊
- **访问频率** — 经常被一起召回的边权重反而升高
- **情感强度** — arousal越高衰减越慢，强烈负面情感（恐惧、羞耻）可能几乎不衰减

L0衰减最慢（核心印象留得久），L3衰减最快（细节先忘）。

### 2.5 不合并原则

不删除或合并旧节点。相似体验通过边连接表达关联，保证原始信息不丢失。

## 三、信息层

### 3.1 实体节点

```
{
  id: "uuid",
  type: "person" | "place" | "concept" | "event" | "skill" | "other",
  name: "张三",
  properties: { ... },                          // 类型专属属性字典
  embedding: [...],                             // name + properties 的语义向量
  created_at: "ISO时间戳",
  updated_at: "ISO时间戳"
}
```

**person 类型的附加字段：**

```
{
  emotion_timeline: [
    { from: "2025-01-01", category: "喜爱", intensity: 0.8 },
    { from: "2026-03-01", category: "淡漠", intensity: 0.2 }
  ],
  emotion_current: { category: "淡漠", intensity: 0.2 }
}
```

### 3.2 属性 vs 节点判断规则

- **节点** — 可以被独立讨论的"东西"（人、组织、地点、事件）
- **属性** — 只在描述某个实体时有意义的值（生日、数量、备注）
- **不确定的** — 先当属性存，后台扫描发现高频共享时自动升级为节点

大概率应为节点：人、组织/公司、地点、时间段/事件

大概率应为属性：物理属性、标量值、描述性文本

### 3.3 关系边

```
{
  from: "uuid_A",
  to: "uuid_B",
  relation: "在XX公司工作",                     // 自由文本
  embedding: [...],                             // relation 文本的语义向量
  confidence: 0.8,                              // 置信度 0-1
  source: "exp_20260329_1430",                  // 来源体验节点ID
  source_type: "direct",                        // 来源类型
  verified_at: null,                            // 上次验证时间
  verify_count: 0,                              // 被验证次数
  created_at: "ISO时间戳"
}
```

### 3.4 来源类型与初始置信度

| source_type | 说明 | 初始 confidence |
|-------------|------|-----------------|
| direct | 用户直接告知 / 亲自观察 | 0.8 |
| external | 从外部资料查到 | 0.6 |
| inferred | 从多条信息推理得出 | 0.5 |
| hearsay | 听说的二手信息 | 0.3 |
| unverified | 来源不明 | 0.1 |

系统永远不承诺真伪，只承诺置信度和来源。

## 四、跨层连接

体验层和信息层之间通过**跨层边**双向连接。

```
{
  from: "exp_20260329_1744",       // 体验节点
  to: "info_uuid_张三",             // 信息层实体
  type: "cross_layer",
  context: "emotion_target",        // 关联原因（情感指向/提及/参与者）
  weight: 0.8                      // 关联强度
}
```

**存储方式：字段 + 边双重存储**

- 体验节点的 `emotion_at_time.target` 字段存ID，用于快速读取
- 额外建一条跨层边，用于反向查询

**双向查询：**

- 从实体出发 → 查所有 `to = 实体ID` 的跨层边 → 拿到关联体验
- 从体验出发 → 查所有 `from = 体验ID` 的跨层边 → 拿到关联实体

支持链式联想：人 → 事 → 人 → 地点 → ...

## 五、self 在记忆系统中的形式

self 在记忆系统中**不承载性格和底线**（那些在独立的核心层），只做两件事：

1. **视角锚点** — 所有体验都以 self 为视角原点
2. **自我认知存储** — 成长记录和状态时间线

```
{
  id: "self",
  role: "perspective_anchor",
  
  growth_log: [
    { at: "2026-03-29", event: "学会了记忆系统的架构设计" }
  ],
  
  state_snapshots: [
    { at: "2026-03-29", mood: "投入", focus: "记忆系统设计" }
  ]
}
```

每个体验节点天然有一条隐含边指向 self（结构约定，不显式存储）。

## 六、三层架构（记忆系统之外）

self 引出的架构决策：记忆系统之外还有两层。

```
┌─────────────────────────┐
│  核心层（Core）          │  性格 · 价值观 · 底线 · 交互基线
│  不在记忆系统内          │  极少变，类似人格DNA
├─────────────────────────┤
│  状态层（State）         │  mood · energy · focus · confidence
│  记忆和核心之间的桥梁    │  随时在变，由体验驱动
├─────────────────────────┤
│  记忆层（Memory）        │  体验 · 信息 · 关系
│  本文档描述的部分        │  存储、检索、衰减
└─────────────────────────┘
```

- 记忆系统可清空/重置，AI核心人格不变
- 核心层参数不允许被记忆直接修改
- 状态层独立可调试

## 七、索引层

- 体验层所有 L0 的语义向量
- 信息层实体 name 和边 relation 的语义向量
- 召回时统一走 RAG 向量检索

---

## 八、边的创建时机

**两者结合：**

- **写入时** — 建显性边（时序边、提及的实体、跨层边）
- **后台定期扫描** — 补隐性边（主题相似、联想、属性升级为节点）

后台整合任务定期运行，类似人类睡眠时的记忆巩固。
