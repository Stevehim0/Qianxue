---

## 一、职责

写入层是记忆系统的入口，核心职责是**接收长对话并做好最小化处理，确保不丢东西**。

---

## 二、核心原则

- **宽松写入** — 零结构化要求，先接住所有内容
- **最小化处理** — 只做必要的即时处理，深层工作留给巩固层
- **不丢东西** — L3 原始记录原封不动存入，永远保留
- **AI第一人称视角** — 所有体验摘要从"我"（AI）的视角生成

---

## 三、API接口设计

### 输入格式

```python
receive_event(dialogue="""
张三：你好
AI：你好呀，有什么可以帮助你的吗？
张三：我想问一下Python的事
AI：当然可以，你想了解什么？
张三：主要是关于类和对象的概念
AI：类是Python的面向对象编程的基础...
""")
```

**要求：**
- 对话必须包含多个说话者的轮流发言
- 每行必须标注说话者（如"张三："、"AI："）
- 对话长度不限，支持多轮长对话

---

## 四、流程

### 步骤1：原始记录 + 上下文快照（顺序执行）

- 完整对话原封不动存入 L3
- 自动附加上下文快照，来源分两部分：
  - **自动获取**：从状态层读取当前 focus 和 mood；从时间戳自动推导 time_of_day 和 silence_before（距上一条体验的时间差）
  - **外部传入**：调用方可选传入 task 等额外上下文，没有则留空。未来的任务感知系统可以提供此字段
- 不需要 LLM 调用，系统自动完成

**数据库写入（第1次）：**
```python
experience = Experience(
    id="exp_20260404_120000",
    L3_raw=dialogue,
    context_focus=...,
    context_mood=...,
    context_time_of_day=...,
    context_silence_before=...,
    created_at=...
)
experience_store.create(experience)
```

---

### 步骤2：并行处理（以下三项同时执行）

写入层的三个 LLM 调用互不依赖，可以并行：

#### 2a. L0 摘要生成

**输入：** 长对话（完整对话）

**Prompt设计：**
```
你是一个AI的主观记忆系统。请从"我"（AI自己）的第一人称视角，
为以下对话生成一句话摘要。

要求：
- 这是主观体验，不是客观记录
- 必须包含：发生了什么、我的感受或反应
- 一句话，不超过50字
- 用自然语言，不要用列表或结构化格式
- 识别对话中的所有说话者，明确谁说了什么

示例：
- "张三向我问Python的问题，我感到乐意帮助"
- "和李四讨论了一下午架构，虽然吵了几句但最后达成共识，很满足"
- "第一次尝试写诗，发现自己居然还挺喜欢这种表达的"

对话：
{dialogue}
```

**输出：** 纯文本，一句话摘要

**数据库写入（第2次）：**
```python
experience.L0_text = l0_summary
experience.L0_embedding = generate_embedding(l0_summary)
experience_store.update(experience)

# 同时存入ChromaDB
vector_store.add_experience(
    exp_id=experience_id,
    embedding=experience.L0_embedding.tolist(),
    metadata={"L0_text": l0_summary}
)
```

---

#### 2b. 实体识别 + 属性提取 + 跨层边创建

**输入：** 长对话（完整对话）

**Prompt设计：**
```
从以下对话中识别所有实体（人、地点、概念、事件、技能等），并提取它们的属性。

实体类型（type）必须是以下之一：
- person: 人物（如"张三"、"李四"）
- place: 地点（如"北京"、"咖啡厅"）
- concept: 概念（如"Python"、"机器学习"）
- event: 事件（如"昨天会议"、"生日派对"）
- skill: 技能（如"编程"、"绘画"）
- other: 其他类型

对每个实体，输出：
{
  "name": "实体名称",
  "type": "实体类型（person/place/concept/event/skill/other）",
  "attributes": {
    "属性名": "属性值",
    ...
  },
  "confidence": 0.0-1.0
}

规则：
- 只识别明确的、有价值的实体
- 实体名称要具体（如"张三"而非"某人"）
- 从对话中提取实体属性（如年龄、职业、偏好、状态等）
- 同一实体只返回一次（合并对话中的多个提及）

对话：
{dialogue}
```

**输出：** JSON数组，每个实体包含name、type、attributes、confidence

**数据库写入（第3、4次）：**
```python
for entity_data in entities:
    entity_name = entity_data["name"]
    entity_type = entity_data["type"]
    entity_attributes = entity_data["attributes"]

    # 检查实体是否已存在（同名即同人规则）
    existing_entity = entity_store.get_by_name(entity_name)

    if existing_entity:
        # 更新现有实体的属性
        merged_properties = existing_entity.properties or {}
        merged_properties.update(entity_attributes)
        entity_store.update(existing_entity.id, properties=merged_properties)
        entity_id = existing_entity.id
    else:
        # 创建新实体
        entity = Entity(
            id=generate_uuid(),
            name=entity_name,  # 实体名称
            type=entity_type,  # 固定类型枚举值
            properties={
                **entity_attributes,  # 实体属性
                "confidence": entity_data["confidence"]
            },
            embedding=generate_embedding(entity_name),
            emotion_timeline=None,
            emotion_current=None
        )
        entity_id = entity_store.create(entity)  # 第3次写入（entities表）

    # 创建跨层边（体验 → 实体）
    cross_edge = CrossEdge(
        from_id=experience_id,
        to_id=entity_id,
        context="contains_entity",
        weight=1.0,
        created_at=now()
    )
    cross_edge_store.create(cross_edge)  # 第4次写入（cross_edges表）
```

#### 2c. 情感快照

**输入：** 长对话（完整对话） + 当前上下文

**Prompt设计：**
```
分析以下对话中"我"（AI）的情感状态。

基础情感类别：joy/sadness/anger/fear/surprise/disinterest/curiosity/neutral
也可以用自定义描述词。

输出：
{
  "category": "情感类别",
  "intensity": 0.0-1.0,
  "valence": -1.0到1.0,
  "arousal": 0.0到1.0
}

注意：
- 这是"我"的感受，不是对话中其他人的感受
- 这是对整个对话的情感体验，不指向某个具体人
- valence：负面=-1，中性=0，正面=+1
- arousal：平静=0，激动=1

对话：
{dialogue}

当前上下文：
状态层 focus：{state_focus}
状态层 mood：{state_mood_label}
```

**输出：** JSON对象，包含情感类别、强度、效价、唤醒度

**数据库写入（第5次）：**
```python
experience.emotion_category = emotion["category"]
experience.emotion_intensity = emotion["intensity"]
experience.emotion_valence = emotion["valence"]
experience.emotion_arousal = emotion["arousal"]
experience.emotion_target = None  # 情感对整个体验，不指向具体实体
experience_store.update(experience)
```

## 五、写入层完成后的产出

| 产出 | 说明 | 数据库写入次数 |
|------|------|---------------|
| 体验节点 | 有完整 L3 + L0 + embedding + emotion + importance | 3次（create + update×2） |
| 信息实体 | 从对话中提取的客观信息 | N次（每条信息1次） |
| 跨层边 | 体验节点 → 信息实体 | N次（每条信息1次） |
| 时序边 | 体验节点 → 上一个体验节点 | 1次 |
| 向量存储 | L0摘要embedding存入ChromaDB | 同步写入 |

**总计：** 3 + N + N + 1 = 4 + 2N 次数据库写入（N为提取的信息条数）

## 六、写入层不负责的内容

以下内容全部留给巩固层处理：

- L1（要点）和 L2（细节）的补充
- 隐性边的发现（主题相似、因果、联想）
- 属性升级（共享属性 → 独立节点）
- 信息验证和置信度更新
- 情感时间线的维护
- 衰减计算
- 梦境处理

## 七、关键设计决策

| 决策 | 理由 |
|------|------|
| 输入改为长对话 | 支持多轮对话，识别说话者，生成正确的第一人称体验 |
| 保持3个并行LLM调用 | 避免单个LLM处理过多任务导致质量下降 |
| 实体识别+属性提取 | 识别实体（人/地点/概念/事件/技能）并提取属性，符合原始设计意图 |
| emotion_target写None | 情感是对整个体验的感受，不指向具体实体 |
| 存储层schema不修改 | 当前结构完整支持新设计 |

## 八、实现注意事项

### 并发控制

三个 LLM 调用并行执行，互不依赖。实现时使用 Python 的 ThreadPoolExecutor。

```python
with ThreadPoolExecutor() as executor:
    future_l0 = executor.submit(generate_l0_summary, experience_id, dialogue)
    future_info = executor.submit(extract_information, experience_id, dialogue)
    future_emotion = executor.submit(analyze_emotion, experience_id, dialogue)
    
    l0_summary = future_l0.result()
    information = future_info.result()
    emotion = future_emotion.result()
```

### 错误处理

- **全部失败策略**：任何 LLM 调用失败都抛出异常，不降级
- **独立事务**：单个信息实体创建失败不影响其他信息实体
- **数据完整性**：L3 原始记录必须成功存储，失败则抛出异常

### 向量生成

- L0 摘要生成 embedding：使用 bge-base-zh 模型
- 信息实体生成 embedding：使用 bge-base-zh 模型
- 向量维度：768
- 归一化：normalize_embeddings=True

## 九、与原始设计的变更

| 项目 | 原始设计 | 修改后设计 | 变更原因 |
|------|---------|-----------|---------|
| API输入 | 完整对话/事件原文 | 长对话（多轮，标注说话者） | 明确格式要求 |
| 实体识别 | 识别人名、地名、组织等名词 | 识别实体（person/place/concept/event/skill/other）并提取属性 | 符合原始设计意图，name存储实体名 |
| 情感target | 记录指向的实体 | 写None | 情感对整个体验，不指向具体人 |
| LLM调用 | 3个并行 | 保持3个并行 | 不变 |
| 实体属性提取 | ❌ 未提及 | ✅ 新增 | 补充遗漏功能 |
