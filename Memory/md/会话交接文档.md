## 一、项目概述

正在为 AI 设计一套仿人类的记忆系统。核心理念：

- **记忆是体验的模糊** — 以"我"为主体的主观体验，不是客观事实的堆砌
- **信息是客观的** — 有真伪，需验证，不属于记忆本身
- **AI 没有真正的自我意识** — 通过虚拟 self 节点模拟主体视角
- **写入宽松，读取严格** — 存储时允许半结构化，召回时校验时效性和适用性

---

## 二、系统架构总览

```
┌─────────────────────────┐
│  核心层（Core）          │  性格 · 价值观 · 底线 · 交互基线
│  独立于记忆系统          │  极少变，类似人格DNA
├─────────────────────────┤
│  状态层（State）         │  mood · energy · focus · confidence
│  核心和记忆之间的桥梁    │  随时在变，由体验驱动
├─────────────────────────┤
│  记忆系统                │
│  ├─ 写入层              │  接收事件，最小化处理
│  ├─ 巩固层（休眠时）     │  深化·关联·整理·做梦
│  ├─ 存储层              │  体验层 + 信息层 + 索引层
│  └─ 召回层              │  触发判断·向量检索·激活扩散·后处理
├─────────────────────────┤
│  个人信息系统（独立）     │  每个人的档案·相处方式·沟通偏好
└─────────────────────────┘
```

## 三、已完成的设计文档

所有文档在 `D:\comp\M\` 目录下：

### 存储层
- **文档**：`存储层设计文档.md`
- **要点**：
  - 双层图结构：体验层（主观）+ 信息层（客观）
  - 体验节点：ID用纯时间戳，L0-L3四层深度（摘要→要点→细节→原始）
  - L0摘要带embedding，召回时只查L0
  - 情感快照存在体验节点上（不变），对人的情感时间线存在信息层（会变）
  - 信息层：实体 + 关系边（自由文本 + embedding + confidence + source_type）
  - 跨层双向连接（字段+边双重存储）
  - self 在记忆系统内只做视角锚点 + 成长记录，性格底线在核心层
  - 属性vs节点：先当属性存，高频共享时后台升级为节点
  - 来源类型：direct(0.8) / external(0.6) / inferred(0.5) / hearsay(0.3) / unverified(0.1)

### 写入层
- **文档**：`写入层设计文档.md`
- **流程图**：`写入层流程图.html`
- **要点**：
  - 步骤1（顺序）：原始记录存L3 + 自动上下文快照（状态层 focus/mood + 时间推导 time_of_day/silence_before + 外部可选 context）
  - 步骤2（并行）：L0摘要生成(LLM) / 即时边创建 / 情感快照
  - L0摘要调LLM生成，速度慢没关系
  - 实体识别同名即同人，允许误会，靠后续修正
  - L1/L2留给巩固层

### 巩固层
- **文档**：`巩固层设计文档.md`
- **流程图**：`巩固层流程图.html`
- **要点**：
  - 触发时机：AI 固定作息时间（睡眠时间段可配置，默认如 02:00-06:00），睡眠期间运行巩固
  - Phase 1（六项并行）：深层提取 / 估值 / 隐性边发现 / 属性升级 / 信息验证 / 情感时间线更新
  - Phase 2（顺序）：衰减计算
  - Phase 3（顺序）：状态层反馈
  - **梦境模块**（四项并行）：
    - 记忆重组：随机抽取不相关节点，LLM分析隐藏联系
    - 情感加工：重新审视高情感体验，调整视角
    - 记忆扭曲：有目标的，按重要度×时间远近决定扭曲程度。重要+近期不扭曲，不重要+久远大幅模糊。L3永远不改
    - 模拟推演：基于记忆生成假设场景，有价值的存为 dream 类型体验
  - 处理策略：按时间先后排序，增量优先，有余力再全量
  - 记忆处理LLM：专门用于梦境模块，prompt和正常对话完全不同

### 召回层
- **文档**：`召回层设计文档.md`
- **流程图**：`召回层流程图.html`
- **要点**：
  - 触发信号（三个，低成本）：实体命中 / 时间指代词 / 状态变化描述
  - 不触发的：情感词、转折词、"又/终于"等
  - 只编码关键词，不编码整句
  - 激活扩散跳数按关系：一般1跳，亲密3跳
  - recall_hint：巩固阶段预生成的自然语言提示，对话时零延迟取用
  - 后处理：轻量模型二分类（说/不说）
  - 深度展开：不自动，AI按需主动调用
  - 个人档案在对话开始时加载为prompt

### 核心层（Core）
- **文档**：`核心层设计文档.md`
- **要点**：
  - 内容形式：第一人称自然语言自述，不是参数表
  - 三层同心圆：不变层（底线）/ 稳定层（性格·价值观）/ 可塑层（表达风格）
  - 修改权限：不变层仅初始设定者、稳定层AI自主判断、可塑层梦境AI自然演化
  - AI以自我为主体，不迎合用户
  - 核心层是"阀门"，决定能做/不能做，不直接改文字
  - 初始自述文本完全由初始设定者亲自撰写
  - 可选结构化锚点用于快速边界检查，但权威来源是自然语言文本

### 状态层（State）
- **文档**：`状态层设计文档.md`
- **要点**：
  - 四个变量：mood（二维坐标+标签）/ energy（数值+标签）/ focus（字符串）/ confidence（数值+标签）
  - mood用效价+唤醒度二维坐标，附带自然语言标签
  - 更新机制：双触发——每10分钟定时更新 + 即时更新（emotion.intensity > 0.8 且距上次更新 > 1分钟时立即触发）
  - 即时更新复用路径A（体验驱动），触发后重置10分钟定时器
  - 有新体验→LLM评估驱动；无新体验→向基线回归
  - 回归速率：energy快，mood慢，具体数值实现时调
  - 核心层约束：状态波动范围受性格限定，超出截断
  - 状态永久持续，没有会话边界（AI是一个人）
  - 影响AI输出的方式：生成状态描述注入prompt，影响表达姿态
  - 巩固层Phase 3的"状态层反馈"已取消，巩固层不再碰状态

### 技术选型
- **文档**：`技术选型文档.md`
- **要点**：
  - Python + SQLite + ChromaDB + bge-base-zh + sentence-transformers
  - LLM统一用千问或DeepSeek，先不分大小模型
  - SQLite表结构：experiences / experience_edges / entities / entity_edges / cross_edges / core / state / person_profiles
  - Embedding用BLOB存储，ChromaDB做向量检索

### 衰减函数
- **文档**：`衰减函数设计文档.md`
- **要点**：
  - 统一公式：`decayed_weight = original × e^(-λ×t) × (1 + α×access) × (1 + β×emotion)`
  - 时间因子（指数衰减）+ 强化因子（访问次数）+ 情感因子（强度保护）
  - L0衰减最慢（λ≈0.01），L3最快（λ≈0.05）
  - 边类型有不同λ：causal最稳定，associative最快淡化
  - 不删除，只降低权重和优先级

### LLM调用设计
- **写入层**：`LLM调用设计-写入层.md` — L0摘要 / 实体识别 / 情感快照，三个prompt，并行执行
- **巩固层+梦境**：`LLM调用设计-巩固层.md` — Phase 1六个prompt + 梦境AI基础设定 + 四个梦境prompt + 可塑层微调prompt
- **召回层后处理**：在召回层设计文档第十章 — 先用LLM二分类，后续替换轻量模型

## 四、个人信息系统（独立于记忆系统）

- **独立存储**，不在记忆系统内
- **渐进创建**：新人只留名字，频繁出现或信息多了再创建档案
- **档案内容**：基本信息 + 相处方式参数 + 沟通偏好 + 边界
- **相处方式由AI主导**：不是迎合对方，而是以自我为主体判断如何相处
- **调整规则**：只收敛不迎合。对方明确反对→收敛；对方没说什么→维持；不存在"对方喜欢就加强"
- **关系影响调整幅度**：关系深→主动适应；关系浅→保持自我
- **更新**：每次巩固阶段由梦境AI检查更新
- **群聊**：加载多人档案，私密记忆不召回

## 五、情感设计

- **对事情的感受** → 体验节点上的快照，不变
- **对人的情感** → 信息层实体上的时间线，会变
- **基础类别**：喜悦/悲伤/愤怒/恐惧/惊讶/厌恶/信任/期待/困惑/满足 + 自由文本
- **情感可指向实体**：emotion_at_time.target 指向信息层
- **情感影响行为**：通过信息层实体的emotion_current影响交互参数
- **回忆时可对比**：当时的感受 vs 现在的感受

## 六、核心设计决策汇总

| 决策 | 结论 |
|------|------|
| 记忆 vs 信息 | 分开，体验层存主观，信息层存客观 |
| AI的自我 | 虚拟self节点模拟，核心层存性格底线 |
| 核心层形式 | 第一人称自然语言自述，三层同心圆（不变/稳定/可塑） |
| 核心层修改 | 不变层仅设定者，稳定层AI自主判断，可塑层梦境AI演化 |
| AI主体性 | 以自我为主体，不迎合用户，只收敛不迎合 |
| 状态变量 | mood/energy/focus/confidence 四个 |
| mood表示 | 效价+唤醒度二维坐标 + 自然语言标签 |
| 状态更新 | 每10分钟定时，与巩固层解耦 |
| 状态回归 | 无刺激时向性格基线回归，energy快mood慢 |
| 状态约束 | 波动范围受核心层性格限定 |
| 状态持久化 | 永久持续，无会话边界 |
| 核心层影响输出 | 阀门——决定能做/不能做 |
| 状态层影响输出 | 姿态——生成状态描述注入prompt |
| 节点最小单位 | L0-L3四层，浅层回忆只看L0，深层展开到L3 |
| 合并策略 | 不合并，用边连接相似体验 |
| 边类型 | temporal/thematic/causal/associative |
| 衰减因素 | 时间 × 访问频率 × 情感强度 |
| 衰减公式 | 指数衰减：original × e^(-λt) × (1+α×access) × (1+β×emotion) |
| 技术栈 | Python + SQLite + ChromaDB + bge-base-zh + 千问/DeepSeek |
| 向量检索 | ChromaDB，体验L0 + 信息层name/relation都有embedding |
| 后处理 | 先用LLM二分类，积累数据后替换轻量分类模型 |
| 信息真伪 | 不承诺真伪，只承诺置信度和来源 |
| 写入策略 | 宽松，只做最小化处理 |
| 巩固触发 | AI 固定作息时间（可配置，默认如 02:00-06:00），睡眠期间运行 |
| 做梦 | 有控制的记忆扭曲 + 重组 + 推演 |
| L3保护 | 原始记录绝对不改 |
| 召回触发 | 实体命中/时间指代/状态变化，三个信号 |
| 编码方式 | 只编码关键词不编码整句 |
| 扩散深度 | 按关系亲疏：1-3跳 |
| recall_hint | 预生成自然语言提示 + LLM后处理过滤 |
| 人际关系 | 独立系统，AI主导，只收敛不迎合 |
| 边创建时机 | 写入时建显性边 + 后台定期补隐性边 |
