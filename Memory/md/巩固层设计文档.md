## 一、职责

巩固层是后台异步运行的，核心职责是**深化、关联、整理、清理、做梦**。在 AI 休眠时运行，模拟人类睡眠时的记忆巩固过程。

---

## 二、核心原则

- **异步处理** — 不阻塞正常对话，在休眠时运行
- **增量优先** — 先处理新增未处理的节点，有余力再全量扫描
- **时间排序** — 按时间先后处理，先处理旧的
- **L3 不可侵犯** — 原始记录永远不改，只改 L0/L1/L2

---

## 三、触发时机

绑定 AI 的固定作息时间。AI 按固定时间表"睡觉"，睡眠期间运行巩固。

### 作息配置

睡眠时间通过配置项定义，不硬编码。配置示例：

```python
# config/settings.py
SLEEP_SCHEDULE = {
    "sleep_time": "02:00",    # 入睡时间（HH:MM，本地时区）
    "wake_time": "06:00",     # 唤醒时间（HH:MM，本地时区）
}
```

- 时间使用本地时区（与 AI 的运行环境一致）
- 可随时调整，不需要改代码
- 未来如需更复杂机制（如空闲触发小睡），在配置中扩展

---

## 四、处理策略

- 优先级：按时间先后排序，先处理旧的
- 范围：先增量处理新节点，处理完后如果还有余力，进行全量扫描
- 并行：Phase 1 内六项任务全部并行，互不依赖

---

## 五、常规巩固流程

### Phase 1 — 并行处理（六项同时执行）

以下六项互不依赖，同时进行：

#### 1. 深层提取

- 对只有 L0 + L3 的节点补充 L1（要点）和 L2（细节）
- 优先处理重要度高但还没补充的节点
- 按时间先后处理

#### 2. 估值

- 计算每个体验节点的重要度评分
- 公式：`importance = 新颖度 × 结果严重性 × 关联密度 × 情感强度`
- 低重要度的节点降低 L1-L2 维护优先级

#### 3. 隐性边发现

- **thematic**：向量相似度扫描，发现主题相似的节点对，建 thematic 边
- **causal**：如果 A 的结果和 B 的起因高度相关，建 causal 边
- **associative**：通过共同关联的实体，间接连接的体验之间建 associative 边

#### 4. 属性升级扫描

- 检查信息层中哪些属性值被多个实体共享
- 超过阈值的属性升级为独立节点

#### 5. 信息层验证

- 检查 confidence 较低且 `verify_count = 0` 的边
- 如果有新的证据支持或反驳，更新 confidence 和 verify_count

#### 6. 情感时间线更新

- 分析近期与某个 person 相关的体验情感倾向
- 如果趋势发生变化，在 `emotion_timeline` 中追加新条目
- 更新 `emotion_current`

### Phase 2 — 衰减计算（依赖 Phase 1 的边变更）

- 重算所有边的 `decayed_weight`
- 衰减因素：时间 × 访问频率 × 情感强度
- 低于阈值的边标记"休眠"但不删除

状态层已改为双触发独立更新（定时10分钟 + 即时触发），巩固层不再碰状态。此Phase已移除。

## 六、梦境模块

在常规巩固完成后运行，由记忆处理 LLM 执行。四项任务并行执行。

### 6.1 记忆重组

- 随机抽取若干不相关的体验节点
- 记忆处理 LLM 分析它们之间可能的隐藏联系
- 发现有意义的新关联 → 建边
- 没有发现 → 丢弃，不留痕迹

### 6.2 情感加工

- 选取情感强度高的体验
- LLM 重新审视这些体验，调整视角
- 可能的输出：降低负面情感的 intensity、强化正面情感
- 修改的不是原始记录（L3），而是 L0/L1 的表述和情感权重

### 6.3 记忆扭曲（有控制的）

扭曲不是随机的，而是有目标的。根据**重要度 × 时间远近**决定扭曲程度：

| 组合 | 处理方式 |
|------|----------|
| 重要 + 近期 | 原样保留，不扭曲 |
| 重要 + 久远 | 保留核心含义和情感，模糊原话和具体细节 |
| 不重要 + 近期 | 轻微模糊，降低 L2 详细程度 |
| 不重要 + 久远 | 大幅模糊，L1 可能只剩标签，L2 清空，只留 L0 + L3 |

**扭曲规则细节：**

- L0 可以改（摘要本身就是主观的）
- L1 可以微调（要点可以重新归纳）
- L2 谨慎改（细节模糊化可以，编造不行）
- L3 绝对不改（原始记录不可侵犯）
- 所有扭曲都有标记，可追溯

**强情感记忆特殊处理：**

强烈的情感本身就是记忆锚点。扭曲方向：
- 保留：`emotion_at_time`、L0 的核心关键词
- 模糊：L1 的具体论述、L2 的细节过程
- 结果："那次争吵让我很愤怒" → 一年后忘了为什么吵、说了什么，但"对张三有过一次很愤怒的争吵"这个印象留着

### 6.4 模拟推演

- 选取近期未解决或反复出现的问题
- LLM 基于相关记忆生成假设场景
- 如果推演产生有价值的结论 → 存为特殊体验节点
- 标记 `source_type: "dream"`，初始 confidence 低于真实体验
- 如果后续被真实经历验证，提升 confidence
- 召回时标注"这是推演得出的，不是真实经历"

## 七、记忆处理 LLM

梦境模块使用专门的记忆处理 LLM，其定位和正常对话 LLM 完全不同：

- **不是在完成任务**，而是在"思考"
- 输入：记忆片段 + 扭曲规则
- 输出：对记忆的结构化修改指令
- Prompt 特点：更发散、更允许出错、自由联想
- 需要包含：当前处理的记忆内容、重要度/时间远近/情感强度、允许的扭曲操作范围、输出格式要求

## 八、讨论决策记录

| 问题 | 决策 |
|------|------|
| 触发频率 | 固定作息时间，在配置文件中设定（默认如 02:00-06:00） |
| 优先级调度 | 按时间先后，先处理旧的 |
| 处理范围 | 增量优先，有余力再全量 |
| 做梦机制 | 增加梦境模块，包含重组/情感加工/扭曲/推演 |
| 扭曲边界 | 有目标地扭曲，按重要度和时间远近组合决定 |
| 强情感处理 | 保留情感锚点，模糊事实细节 |
| L3 保护 | 原始记录绝对不改 |
| 并行处理 | Phase 1 六项并行，梦境四项并行 |
| 状态层更新 | 已从巩固层移除，状态层双触发独立更新（定时10分钟 + 即时触发） |
